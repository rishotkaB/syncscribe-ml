# Контракт 2.0: поля, типы и значения

Обмен JSON-файлами между SyncBack и ML-конвейером. SyncBack отправляет один файл-запрос на документ, конвейер возвращает один файл-ответ. Кодировка UTF-8. Пример запроса: `data/contract/example_request.json`.

## Запрос (SyncBack → ML)

| Поле | Тип | Обязательно | Значения и правила |
|---|---|---|---|
| `request_id` | string | нет | Любая строка, обычно UUID. Возвращается в ответе без изменений. |
| `analysis_job_id` | string | нет | Любая строка, обычно UUID. Возвращается в ответе без изменений. |
| `document` | object | да | Документ, который проверяем. |
| `document.id` | string | нет | Не используется, для логов. |
| `document.name` | string | нет | Не используется, для логов. |
| `document.format` | string | нет | `docx`, `md`, `txt` и т. п. Не влияет на обработку: документ уже разбит на блоки. |
| `document.blocks` | array of object | да | Блоки в порядке следования в документе. |
| `blocks[].block_id` | string | да | Уникален внутри документа. На него ссылаются правки. |
| `blocks[].type` | string | нет, по умолчанию `paragraph` | `heading` — заголовок: не проверяется, задаёт раздел для следующих блоков. Любое другое значение (`paragraph`, `list_item`, `table_cell` …) — обычный текст. |
| `blocks[].text` | string | да | Текст блока как в документе. `old_text` и `insert_after` в ответе берутся из него дословно. |
| `blocks[].editable` | boolean | нет, по умолчанию `true` | `false` — блок не проверяется и не правится. |
| `source` | object | да, если нет `sources` | Источник истины. |
| `sources` | array of object | да, если нет `source` | Несколько источников сразу. Только так видны противоречия между источниками. |
| `source.text` | string | да | Непустой текст. Пустые строки делят его на абзацы, строки на `-`, `*`, `•`, `1.` — на пункты списка, `# …` — на разделы. |
| `source.name` | string | нет | Показывается в `rationale` («… (Решения встречи от 02.11.2026)»). Если нет — берётся `id`. |
| `source.id`, `source.type` | string | нет | Не используются. |

Лишние поля запроса игнорируются.

## Ответ (ML → SyncBack)

| Поле | Тип | Значения |
|---|---|---|
| `contract_version` | string | Всегда `"2.0"`. |
| `request_id` | string \| null | Из запроса; `null`, если в запросе не было. |
| `analysis_job_id` | string \| null | Из запроса; `null`, если в запросе не было. |
| `status` | string | `completed` — анализ прошёл, `suggestions` можно применять; `failed` — см. `error`, `suggestions` пустой. |
| `suggestions` | array of object | Правки по порядку блоков в документе. Пустой список — правок нет. |
| `flags` | array of object | Пометки «проверьте вручную» без готовой правки. Сверх договорённого, можно игнорировать. |
| `meta` | object | Статистика прогона (число вызовов модели, время). Состав ключей может меняться, не опирайтесь на него. |
| `error` | object \| null | `null` при `completed`. |

### suggestions[]

| Поле | Тип | modify | add |
|---|---|---|---|
| `suggestion_id` | string | `s-1`, `s-2`, … уникален в ответе | то же |
| `change_type` | string | `"modify"` | `"add"` |
| `target_block_id` | string | Блок, в котором заменяем текст | Блок, после текста которого вставляем |
| `old_text` | string \| null | Дословная подстрока `text` этого блока: весь блок или одно изменённое предложение | `null` |
| `new_text` | string | Чем заменить `old_text` | Что вставить: одно-два предложения |
| `insert_after` | string \| null | `null` | Дословно последнее предложение блока `target_block_id` |
| `rationale` | string | Почему нужна правка + цитата источника в «…» и имя источника в скобках. Если `confidence_score` < 0.7, в конце «Проверьте внимательно: <причина>». | то же |
| `confidence_score` | number | 0–1, два знака, см. ниже | то же |

`change_type = "delete"` зарезервирован, сейчас конвейер его не возвращает.

Как применять: для `modify` найти `old_text` в тексте блока `target_block_id` и заменить на `new_text`. Для `add` вставить `new_text` сразу после `insert_after` в блоке `target_block_id`, через пробел (или отдельным абзацем, как решит UI). Для одного блока сначала идёт `modify`, потом `add`.

### confidence_score

Считается в коде по проверяемым признакам. Берётся наименьшее из подходящих значений.

| Значение | Когда |
|---|---|
| 0.97 | `modify` меняет только значение (число, срок, версию), значение есть в цитате, его подтверждают два источника |
| 0.95 | то же, один источник |
| до 0.80 | `add` |
| до 0.75 | `modify` переписывает формулировку, а не одно значение |
| до 0.60 | нового значения нет в цитате источника; источники расходились, но проверка сочла это разными объектами; `add` объединяет несколько фактов |
| до 0.40 | цитаты, на которую опирается правка, нет в источнике дословно |
| ниже 0.70 | модель сама поставила оценку ниже 0.7 |

Оценка не откалибрована на реальных данных. Рекомендуемый порог показа в UI — по договорённости с продуктом. Для калибровки нам нужны решения пользователей: принял, отклонил, исправил.

### flags[]

| Поле | Тип | Значения |
|---|---|---|
| `flag_id` | string | `f-1`, `f-2`, … |
| `reason` | string | `sources_conflict` — источники противоречат друг другу по этому месту. Правку не предлагаем, решает человек. |
| `target_block_id` | string | Блок, который нужно проверить |
| `old_text` | string | Текст блока целиком |
| `rationale` | string | Пояснение для пользователя |
| `quotes` | array of `{source: string, text: string}` | По цитате из каждого спорящего источника; `source` — его `name` |

### error

| Поле | Тип | Значения |
|---|---|---|
| `code` | string | `invalid_request` — запрос не по контракту (нет `document.blocks`, у блока нет `block_id` или `text`, `block_id` повторяется, нет источника или его `text` пустой). `pipeline_error` — сбой при анализе (модель недоступна, ответ модели не по схеме). |
| `message` | string | Описание по-русски, для логов. |
